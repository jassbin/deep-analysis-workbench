# 深度分析工作台 · Deep Analysis Workbench（Web MVP v0.1）

把三个 skill（deep-analysis / structural-navigator / resonant-cognition）产品化为「推理轨迹平台」的可运行前端原型。
零依赖（纯 HTML/CSS/JS），桌面与手机浏览器均可打开。

## 怎么运行

方式一（最简单）：直接双击打开 `index.html`（无联网检索）。

方式二（本地服务器，推荐，含联网检索 + 静态服务）：

```
cd app
node server.js   # 监听 127.0.0.1:8931，含 /api/search（自动探测系统代理）
# 或纯静态：python -m http.server 8931 --directory app（无检索）
```

然后访问 `http://localhost:8931/`（工作台）或 `http://localhost:8931/cases.html`（案例库）。

## 页面

| 文件 | 说明 |
|------|------|
| `index.html` | 7 步分析流水线工作台：推理链 + 步骤详情 + 检查器（证据/置信度/批注） |
| `cases.html` | 案例库·推理轨迹卡（v2：异常候选淘汰→撕裂路径→游走轨迹→碰壁记录→结论+可证伪条件） |

## 已实现的特色（对应产品方案「附3」）

- **7 步流水线**：材料与信源 → 异常锁定 → 中性骨架 → 机制穿透 → 博弈与类比 → 情景分支 → 对抗质检。
- **异常候选仲裁**：3 个候选异常按杠杆率评分，可切换入口（撕错了重撕）。
- **步骤干预 + 下游重算**：任意步骤「我不同意」→ 标记已修改 → 下游全部标「需重算」→ 一键重算。
- **审校会话**：交叉质询，系统必须落「辩护 / 让步并修订 / 挂起」三选一，附自动审校摘要。
- **中性/对抗双模式**：对抗模式下的利益流向与重命名为对抗性解释，非事实判断。
- **联网检索**：输入事件 → `/api/search`（百度百科 + DuckDuckGo + Brave + 必应，自动走系统代理，按关键词相关性过滤）→ 勾选「加入材料」并入步骤 1。
- **响应式**：桌面三栏 → 平板两栏 → 手机单栏堆叠，触屏友好。

## 目录结构

```
app/
├─ index.html      # 工作台
├─ server.js       # 本地服务：静态资源 + /api/search 联网检索
├─ cases.html      # 案例库
├─ css/style.css   # 响应式样式（@media 1080px / 720px）
└─ js/
   ├─ data.js      # 种子数据：瑞幸库迪 7 步演示 + 3 张推理轨迹卡
   └─ app.js       # 状态机、渲染、交互（异常仲裁/修订重算/审校协议/导出）
```

## 如何接 LLM 后端（下一步）

当前是纯前端演示，数据在 `js/data.js`。接后端时：
1. 把 `SEED` 替换为 API 返回的结构（`steps` 每步 = `{id, name, status, title, body}`，body 内容字段见各步骤渲染分支）。
2. 在 `app.js` 中把「重算下游」「审校质询」两处从本地逻辑改为调用 `/api/analyze`、`/api/review`。
3. 案例库 `CASES` 改为从 `/api/cases` 拉取，入库单位为推理轨迹卡（见 `cases.html` 渲染格式）。
